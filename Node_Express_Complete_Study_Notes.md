## 2. Node.js fundamentals

**Node.js is a JavaScript runtime**: it runs JavaScript outside the browser, including on a backend server. It is **not** a programming language and **not** a framework.

- **JavaScript:** The language.
- **Node.js:** The runtime that executes JavaScript on the server.
- **Express.js:** A framework/package running on Node.js that simplifies web servers and APIs.
- **npm:** The package manager used to install dependencies and run scripts.

Node provides built-in APIs such as `node:http`, `node:fs/promises`, `node:path`, and `node:crypto`.

```js
import http from "node:http";
import fs from "node:fs/promises";
import { randomUUID } from "node:crypto";
```

A backend receives requests, performs work (validation, data operations), and sends responses. A React frontend can call that backend using `fetch()`.

## 3. Modules, npm, and package.json

### ES Modules

Use `"type": "module"` in `package.json` to enable `import` and `export` in `.js` files.

```js
// math.js
export function add(a, b) {
  return a + b;
}

// app.js
import { add } from "./math.js";
console.log(add(2, 3)); // 5
```

- **Named export:** `export function ...` → `import { name } from ...`.
- **Default export:** `export default router` → `import router from ...`.
- For local ES Module imports, include the file extension: `"./tasks.js"`.

### npm commands

```bash
npm init -y          # Create package.json
npm install express  # Add Express dependency
npm run dev          # Run the dev script
npm start            # Run the start script
```

`package.json` defines metadata, dependencies, and scripts. `package-lock.json` records the resolved dependency tree. `node_modules/` contains installed packages and should not be committed to Git.

**Example scripts (inside package.json):**

```json
{
  "type": "module",
  "scripts": {
    "start": "node --env-file=.env server.js",
    "dev": "node --watch --env-file=.env server.js"
  }
}
```

Keep any actual `dependencies` generated by npm; don't replace installed version numbers with examples.

### Common npm problem: EJSONPARSE

`EJSONPARSE: Unexpected end of JSON input` means `package.json` is empty or invalid JSON. Fix the file, save it, and retry `npm install express`.

JSON rules: double-quoted keys and strings; no comments or trailing commas.

## 4. Files, paths, JSON, and environment variables

### Read and write files

```js
import fs from "node:fs/promises";

const filePath = new URL("./tasks.json", import.meta.url);

const text = await fs.readFile(filePath, "utf8");
const tasks = JSON.parse(text); // JSON text -> JS array/object

await fs.writeFile(filePath, JSON.stringify(tasks, null, 2));
```

- `fs.readFile()` reads asynchronously.
- `fs.writeFile()` writes/replaces file content asynchronously.
- `JSON.parse()` converts JSON **text** into a JavaScript value.
- `JSON.stringify()` converts a JavaScript value into JSON **text**.
- `new URL("./tasks.json", import.meta.url)` resolves relative to the module file, not the terminal's working directory.
- `ENOENT` means a file or directory was not found.

**JSON file example:**

```json
[
  {
    "id": "abc123",
    "title": "Learn Express",
    "completed": false
  }
]
```

### Environment variables

`.env`:

```dotenv
PORT=5000
```

`server.js`:

```js
const PORT = Number(process.env.PORT) || 5000;
```

`node --env-file=.env server.js` loads `.env` values into `process.env`. `--watch` restarts the process when files change. Use a Node.js version supporting these flags.

At the workspace root, `.gitignore`:

```gitignore

```

Create `.env.example` containing safe sample configuration such as `PORT=5000`; don't put real secrets in it.

## 5. Async JavaScript, Promises, and the event loop

### Synchronous vs asynchronous

- **Synchronous:** Work happens in sequence; a blocking operation can stop progress.
- **Asynchronous:** Operations such as file I/O can be started without blocking the JavaScript thread while waiting for I/O.

A **Promise** represents an asynchronous result: pending, fulfilled, or rejected.

```js
async function loadTasks() {
  try {
    const text = await fs.readFile(filePath, "utf8");
    return JSON.parse(text);
  } catch (error) {
    console.error(error);
    throw error;
  }
}
```

- An `async` function always returns a Promise.
- `await` waits for the Promise to settle **inside that async function**.
- `try/catch` handles synchronous errors and rejections from awaited Promises.
- `throw` propagates an error to the caller.

### Event loop (basic mental model)

Node.js runs JavaScript callbacks on an event loop. It can coordinate many I/O operations efficiently without creating a separate JavaScript thread for every request. It does **not** mean all JavaScript runs in parallel; heavy CPU-bound JavaScript can still block the event loop.

**Important:** Awaiting a file read does not block the entire Node.js process in the same way as synchronous file I/O.

## 6. HTTP, REST, CRUD, and status codes

An HTTP request contains a method, URL, headers, and optionally a body. A response contains a status code, headers, and optionally a body.

| CRUD operation | HTTP method | Endpoint | Purpose |
|---|---|---|---|
| Read all | GET | `/tasks` | List tasks |
| Read one | GET | `/tasks/:id` | Get a specific task |
| Create | POST | `/tasks` | Add a task |
| Update partially | PATCH | `/tasks/:id` | Change selected fields |
| Delete | DELETE | `/tasks/:id` | Remove a task |

**Useful status codes:**

| Code | Meaning | Example |
|---:|---|---|
| 200 | OK | GET/PATCH success |
| 201 | Created | POST success |
| 204 | No Content | DELETE success; no response body |
| 400 | Bad Request | Invalid title or JSON |
| 404 | Not Found | Task ID/route missing |
| 413 | Content Too Large | Oversized request body |
| 500 | Internal Server Error | Unexpected server failure |

**REST** is an API design style built around resources (like `tasks`), HTTP methods, and consistent responses.

### Main server concept

```js
import http from "node:http";

const server = http.createServer(async (req, res) => {
  // Manually inspect req.method and req.url.
  // Parse request bodies and send responses yourself.
});

server.listen(4000, () => {
  console.log("Server running on port 4000");
});
```

In plain Node.js, you are responsible for:

1. Checking `req.method` and URL/pathname.
2. Matching dynamic IDs in paths like `/tasks/:id`.
3. Collecting and parsing request body data.
4. Setting response status and JSON headers.
5. Calling `res.end()` to finish the response.
6. Handling errors.

For example, a manual response helper might look like:

```js
function sendJson(res, status, data) {
  res.writeHead(status, { "Content-Type": "application/json" });
  res.end(JSON.stringify(data));
}
```

The task data functions (`getTasks`, `getTaskById`, `createTask`, `updateTask`, `deleteTask`) live in `tasks.js`. The HTTP server calls them. This separation already existed before Express.

### Express server basics

```js
import express from "express";

const app = express();
const PORT = Number(process.env.PORT) || 5000;

app.use(express.json());

app.get("/", (req, res) => {
  res.json({ message: "Welcome to Express Task Manager API" });
});

app.listen(PORT, () => {
  console.log(`Express server running at http://localhost:${PORT}`);
});
```

- `express()` creates an Express app.
- `app.get(path, handler)` registers a GET route.
- `app.post`, `app.patch`, and `app.delete` register other methods.
- `res.status(201).json(data)` sets the status and sends JSON.
- `app.listen()` starts an HTTP server.
- Express is built on Node.js, not a replacement for Node.js.

### Sample routes

```js
app.get("/tasks", async (req, res) => {
  const tasks = await getTasks();
  res.status(200).json(tasks);
});

app.get("/tasks/:id", async (req, res) => {
  const task = await getTaskById(req.params.id);
  if (!task) return res.status(404).json({ error: "Task not found" });
  res.json(task);
});

app.post("/tasks", validateTask, async (req, res) => {
  const task = await createTask(req.body.title.trim());
  res.status(201).json(task);
});
```

## 9. Express request data and middleware

### `req.params` vs `req.query` vs `req.body`

| Property | Comes from | Example | Result |
|---|---|---|---|
| `req.params.id` | Path parameter | `/tasks/abc123` | `"abc123"` |
| `req.query.completed` | Query string | `/tasks?completed=true` | `"true"` |
| `req.body.title` | JSON body | `{ "title": "Study" }` | `"Study"` |

**Important:** Path IDs and query values are usually strings. `"true"` is **not** the boolean `true`.

### Filter tasks by completion

```js
app.get("/tasks", async (req, res) => {
  const tasks = await getTasks();
  const { completed } = req.query;

  if (completed === undefined) return res.json(tasks);

  if (completed !== "true" && completed !== "false") {
    return res.status(400).json({
      error: "completed must be true or false"
    });
  }

  const wanted = completed === "true";
  res.json(tasks.filter(task => task.completed === wanted));
});
```

### Middleware

Middleware runs during request processing and can inspect/modify the request, send a response, or pass control onward.

```js
app.use(express.json()); // Parse JSON bodies before POST/PATCH handlers

app.use((req, res, next) => {
  console.log(`${req.method} ${req.path}`);
  next(); // Continue processing
});
```

If middleware neither sends a response nor calls `next()` (or forwards an error), the request can remain pending. **Order matters:** register JSON parsing and logging before the routes; unknown-route and error handlers afterward.

## 10. Validation and error handling

### Reusable validation middleware

`express-js/middleware/validateTask.js`:

```js
export function validateTask(req, res, next) {
  const { title } = req.body ?? {};

  if (typeof title !== "string" || title.trim().length < 3) {
    return res.status(400).json({
      error: "Title must contain at least 3 characters"
    });
  }

  next();
}
```

Attach it to the POST route:

```js
app.post("/tasks", validateTask, async (req, res) => {
  const task = await createTask(req.body.title.trim());
  res.status(201).json(task);
});
```

**Why?** The middleware validates; the route creates the task. This is **separation of concerns**.

### PATCH validation notes

- Accept `title`, `completed`, or both.
- `title`, when provided, must be a string with at least 3 non-space characters.
- `completed`, when provided, must be a boolean.
- Check `completed !== undefined`, **not** `if (completed)`, because `false` is valid.
- Return 400 for missing/invalid updates and 404 for a nonexistent task.

### Central error handler

```js
// Register AFTER your routes and unknown-route handler.
app.use((err, req, res, next) => {
  console.error(err);

  if (res.headersSent) return next(err);

  if (err.type === "entity.parse.failed") {
    return res.status(400).json({ error: "Invalid JSON" });
  }

  if (err.type === "entity.too.large") {
    return res.status(413).json({ error: "Request body too large" });
  }

  res.status(500).json({ error: "Internal server error" });
});
```

Error middleware has **four arguments**: `(err, req, res, next)`. Express 5 automatically forwards thrown errors/rejected Promises from async route handlers to error middleware. Avoid exposing raw internal error details in production responses.

### Unknown routes

```js
app.use((req, res) => {
  res.status(404).json({ error: "Route not found" });
});
```

This goes after the valid routes so it doesn't intercept them.

### `routes/taskRoutes.js` (complete)

import { Router } from "express";

### `controllers/taskController.js` (complete)

```js
import {
  getTasks,
  getTaskById,
  createTask,
  updateTask,
  deleteTask
} from "../services/taskService.js";

export async function getAllTasks(req, res) {
  const tasks = await getTasks();
  const { completed } = req.query;

  if (completed === undefined) return res.status(200).json(tasks);
  if (completed !== "true" && completed !== "false") {
    return res.status(400).json({ error: "completed must be true or false" });
  }

  res.status(200).json(
    tasks.filter(task => task.completed === (completed === "true"))
  );
}

export async function getSingleTask(req, res) {
  const task = await getTaskById(req.params.id);
  if (!task) return res.status(404).json({ error: "Task not found" });
  res.status(200).json(task);
}

export async function addTask(req, res) {
  const task = await createTask(req.body.title.trim());
  res.status(201).json(task);
}

export async function editTask(req, res) {
  const body = req.body;
  if (!body || typeof body !== "object" || Array.isArray(body)) {
    return res.status(400).json({ error: "Invalid task data" });
  }

  const { title, completed } = body;
  if (title === undefined && completed === undefined) {
    return res.status(400).json({ error: "Provide title or completed" });
  }
  if (title !== undefined &&
      (typeof title !== "string" || title.trim().length < 3)) {
    return res.status(400).json({
      error: "Title must contain at least 3 characters"
    });
  }
  if (completed !== undefined && typeof completed !== "boolean") {
    return res.status(400).json({ error: "Completed must be true or false" });
  }

  const updates = {};
  if (title !== undefined) updates.title = title.trim();
  if (completed !== undefined) updates.completed = completed;

  const task = await updateTask(req.params.id, updates);
  if (!task) return res.status(404).json({ error: "Task not found" });
  res.status(200).json(task);
}

export async function removeTask(req, res) {
  const deleted = await deleteTask(req.params.id);
  if (!deleted) return res.status(404).json({ error: "Task not found" });
  res.status(204).send();
}
```

### `services/taskService.js` (complete)

```js
import fs from "node:fs/promises";
import { randomUUID } from "node:crypto";

const filePath = new URL("../data/tasks.json", import.meta.url);

export async function getTasks() {
  const data = await fs.readFile(filePath, "utf8");
  return JSON.parse(data);
}

async function saveTasks(tasks) {
  await fs.writeFile(filePath, JSON.stringify(tasks, null, 2));
}

export async function getTaskById(id) {
  const tasks = await getTasks();
  return tasks.find(task => task.id === id) ?? null;
}

export async function createTask(title) {
  const tasks = await getTasks();
  const newTask = { id: randomUUID(), title, completed: false };
  tasks.push(newTask);
  await saveTasks(tasks);
  return newTask;
}

export async function updateTask(id, updates) {
  const tasks = await getTasks();
  const task = tasks.find(task => task.id === id);
  if (!task) return null;
  if (updates.title !== undefined) task.title = updates.title;
  if (updates.completed !== undefined) task.completed = updates.completed;
  await saveTasks(tasks);
  return task;
}

export async function deleteTask(id) {
  const tasks = await getTasks();
  const remainingTasks = tasks.filter(task => task.id !== id);
  if (remainingTasks.length === tasks.length) return false;
  await saveTasks(remainingTasks);
  return true;
}
```

## 12. Compare the three projects

| Topic | Plain Node.js | Basic Express | Structured Express |
|---|---|---|---|
| Runtime | Node.js | Node.js | Node.js |
| HTTP layer | Built-in `node:http` | Express | Express |
| Route matching | Manual conditions | `app.get/post/...` | `Router()` |
| Request JSON | Manually parse | `express.json()` | `express.json()` |
| Route parameters | Manually extract | `req.params` | `req.params` in controllers |
| Query parameters | Manually parse URL | `req.query` | `req.query` in controllers |
| Response JSON | `res.end(JSON.stringify(...))` | `res.json()` | `res.json()` in controllers |
| Validation | Server logic | Middleware + routes | Dedicated middleware |
| Task operations | `tasks.js` | `tasks.js` | `services/taskService.js` |
| Storage | `tasks.json` | `tasks.json` | `data/tasks.json` |
| Main benefit | Understand HTTP internals | Less boilerplate | Maintainability |

**Critical insight:** Express doesn't replace Node.js. The third project doesn't introduce a new framework; it **organizes the same Express functionality** into separate files.

### The three responsibilities

1. **Route:** Which endpoint is requested?
2. **Controller:** How should the HTTP request/response be handled?
3. **Service:** What operation should be performed on data?

For example, `POST /tasks`:

```text
router.post("/", validateTask, addTask)
  -> validateTask checks req.body.title
  -> addTask calls createTask(title)
  -> createTask writes data/tasks.json
  -> addTask sends HTTP 201 + new task
```

## 13. Postman testing checklist

Use a separate Postman collection for each project:

- **Task Manager API** → `http://localhost:4000`
- **Express Task Manager API** → `http://localhost:5000`
- **Express Structured API** → `http://localhost:6000`

Optionally create a collection variable called `baseUrl` and use `{{baseUrl}}/tasks` in requests.

| Test | Method | URL | Body | Expected |
|---|---|---|---|---|
| List all | GET | `/tasks` | — | 200, array |
| Create | POST | `/tasks` | `{ "title": "Learn Express" }` | 201, task with UUID |
| Get one | GET | `/tasks/<real-id>` | — | 200, task |
| Update | PATCH | `/tasks/<real-id>` | `{ "completed": true }` | 200, updated task |
| Delete | DELETE | `/tasks/<real-id>` | — | 204, empty body |
| Completed only | GET | `/tasks?completed=true` | — | 200, filtered array |
| Incomplete only | GET | `/tasks?completed=false` | — | 200, filtered array |
| Bad filter | GET | `/tasks?completed=yes` | — | 400 |
| Invalid title | POST | `/tasks` | `{ "title": "Hi" }` | 400 |
| Missing task | GET | `/tasks/nonexistent` | — | 404 |
| Unknown route | GET | `/unknown` | — | 404 |
| Invalid JSON | POST | `/tasks` | Malformed JSON with JSON content type | 400 |

**Postman setup:** For POST/PATCH, choose **Body → raw → JSON**. For routes with `<real-id>`, copy the actual ID returned by POST. Save requests in the appropriate collection; you can export a collection as JSON for backup.

| `EJSONPARSE` during `npm install` | Empty/invalid `package.json` | Replace with valid JSON; save; retry |
| `Cannot use import statement outside a module` | ES Modules not enabled | Add `"type": "module"` |
| `ERR_MODULE_NOT_FOUND` | Wrong relative import path or missing `.js` | Check paths and file extensions |
| `req.body` is undefined | Missing `express.json()` or incorrect request body | Add middleware before routes; send JSON content type |
| Postman request keeps loading | Middleware did not respond or call `next()` | Ensure every path continues or responds |
| All requests return 404 | Wrong route order or mount path | Mount router before fallback 404 |
| `GET /tasks/:id` returns 404 | Incorrect ID | Use UUID returned from POST |
| Port already in use (`EADDRINUSE`) | Another server uses that port | Stop the other server or change `PORT` |
| `tasks.json` parse error | Invalid JSON | Repair file; initialize with `[]` if appropriate |
| `completed=false` doesn't update | Used `if (completed)` | Use `completed !== undefined` |
| Changed `.env` but port didn't change | Old process still running or script not loading `.env` | Restart and verify `--env-file=.env` |

### Practical caveats

- JSON-file storage is good for learning, **not** robust for concurrent requests: simultaneous read-modify-write operations can lose updates.
- The example service expects `data/tasks.json` to exist and contain valid JSON.
- The sample code validates task titles but is not a complete production security solution.
- Do not expose `.env` secrets in Git or frontend code.

## 17. Buffers and Streams in Node.js

### 17.1 The big idea

- **Buffer:** An object that holds raw bytes in memory. Useful when working with binary data such as images, file contents, and network messages.
- **Stream:** An interface for reading, writing, or transforming data **piece by piece**, instead of requiring the entire data set to be available at once.
- **Relationship:** A readable stream often emits **Buffer chunks**. A Buffer is the data container; a stream manages the flow of data.

**Example:** For a 1 GB file, `readFile()` loads the file's contents into memory before resolving. A readable stream can process chunks as they arrive, typically using much less memory.

### 17.2 Buffer basics

```js
const buffer = Buffer.from("Hello");

console.log(buffer);                 // <Buffer 48 65 6c 6c 6f>
console.log(buffer.toString("utf8")); // Hello
console.log(buffer.length);          // 5 bytes
console.log(buffer[0]);              // 72 (the byte for H)
console.log(Buffer.isBuffer(buffer)); // true

const empty = Buffer.alloc(10);       // 10 bytes, initialized to zero
```

`48 65 6c 6c 6f` are **hexadecimal** byte values for the UTF-8 encoding of `Hello`. `Buffer.length` measures **bytes**, not characters: some Unicode characters take multiple UTF-8 bytes.

```js
console.log(Buffer.byteLength("Hello", "utf8")); // 5
console.log(Buffer.byteLength("😊", "utf8"));    // 4
```

**When to use Buffers:** binary files, network protocols, encryption APIs, and other operations requiring bytes. You do not need Buffers for ordinary JavaScript strings or simple JSON objects.

### 17.3 Reading files: `readFile()` vs `createReadStream()`

**Read the entire file:**

```js
import fs from "node:fs/promises";

const text = await fs.readFile("./sample.txt", "utf8");
console.log(text);
```

This is appropriate for small files, including the `tasks.json` files used in our Task Manager projects.

**Read progressively:**

```js
import fs from "node:fs";

const stream = fs.createReadStream("./sample.txt");

stream.on("data", (chunk) => {
  console.log("Chunk bytes:", chunk.length);
  console.log("Is Buffer?", Buffer.isBuffer(chunk)); // true by default
  console.log(chunk.toString("utf8"));
});

stream.on("end", () => {
  console.log("Finished reading");
});

stream.on("error", (error) => {
  console.error("Read failed:", error.message);
});
```

**Events:** `data` means a chunk arrived; `end` means no more data; `error` means the operation failed. With `createReadStream("./sample.txt", { encoding: "utf8" })`, the chunks are strings instead of Buffers. For text with multibyte characters, setting an encoding handles characters that span chunk boundaries.

### 17.4 The four types of Node.js streams

| Type | What it does | Example |
|---|---|---|
| **Readable** | Produces data to read | `fs.createReadStream()` |
| **Writable** | Accepts data to write | `fs.createWriteStream()` |
| **Duplex** | Both reads and writes | TCP socket |
| **Transform** | Reads, changes, and writes data | Compression stream |

Start with **Readable** and **Writable**; learn custom Duplex/Transform streams later.

### 17.5 Writing a file using a stream

```js
import fs from "node:fs";

const writable = fs.createWriteStream("./output.txt");

writable.write("Hello\n");
writable.write("Learning Node.js\n");
writable.end("Finished!\n");

writable.on("finish", () => console.log("All writes finished"));
writable.on("error", (err) => console.error(err.message));
```

`write()` supplies data to the stream; `end()` says there will be no more writes. `finish` indicates the queued writes have completed. For large or fast repeated writes, respect the return value of `write()` and the `drain` event to avoid excessive buffering.

### 17.6 `pipe()` and `pipeline()`

**`pipe()` connects a readable stream to a writable stream:**

```js
import fs from "node:fs";

const source = fs.createReadStream("./sample.txt");
const destination = fs.createWriteStream("./copy.txt");

source.pipe(destination);
```

Data flows chunk by chunk. `pipe()` handles **backpressure**: it slows or pauses reading when the destination cannot keep up. However, handling errors and completion across multiple streams takes extra work.

**Prefer `pipeline()` for robust file-copy examples:**

```js
import fs from "node:fs";
import { pipeline } from "node:stream/promises";

try {
  await pipeline(
    fs.createReadStream("./sample.txt"),
    fs.createWriteStream("./copy.txt")
  );
  console.log("File copied successfully");
} catch (error) {
  console.error("Copy failed:", error.message);
}
```

`pipeline()` manages stream completion, propagates errors, and handles cleanup better than a bare `pipe()` call.

### 17.7 Streams in Express.js

Our Task Manager uses `res.json(tasks)` for small API responses; that is still the right approach. Streams become especially useful for serving large files or handling uploads.

```js
import express from "express";
import fs from "node:fs";
import { pipeline } from "node:stream/promises";

const app = express();

app.get("/download", async (req, res, next) => {
  try {
    res.type("text/plain");
    await pipeline(fs.createReadStream("./sample.txt"), res);
  } catch (error) {
    if (!res.headersSent) next(error);
    else console.error("Download interrupted:", error);
  }
});

app.use((err, req, res, next) => {
  console.error(err);
  if (res.headersSent) return next(err);
  res.status(500).json({ error: "Internal server error" });
});

app.listen(6000);
```

Here `res` is a writable HTTP response stream. Express also offers `res.download()` for ordinary downloads; you don't always need to write streaming code yourself.

### 17.8 Quick comparison

| Concept | Main purpose | Holds all file data at once? |
|---|---|---|
| `Buffer` | Store bytes | Depends on what you put in it |
| `fs.readFile()` | Read a complete file | Yes, before returning |
| `fs.createReadStream()` | Read progressively | Normally no |
| `fs.createWriteStream()` | Write progressively | Normally no |
| `pipe()` / `pipeline()` | Connect data streams | Normally no |

**Important:** `readFile()` can return a Buffer if you omit the encoding, but that does **not** make `readFile()` a stream.
